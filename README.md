# SQL: продуктовые метрики

Запросы на основные продуктовые метрики: retention, когортный анализ, DAU/MAU и sticky factor, воронка, оконные функции.
Написаны в ходе обучения продуктовой аналитике. Данные **учебные и синтетические**, они нужны, чтобы каждый запрос можно было запустить и проверить.

## Что внутри

| Файл | Метрика | Что показывает | Конструкции |
| --- | --- | --- | --- |
| `01_retention.sql` | Retention D7 | Доля пользователей, вернувшихся на 7-й день: classic и rolling | CTE, JOIN, `COUNT(DISTINCT CASE)` |
| `02_cohort_table.sql` | Когортный анализ | Retention D1 и D7 отдельно по каждой когорте | CTE, `GROUP BY` |
| `03_dau_mau_sticky.sql` | DAU / MAU / sticky | Какая доля месячной аудитории заходит в обычный день | CTE, подзапрос |
| `04_funnel.sql` | Воронка | Конверсии install → signup → subscribe | CTE, условный подсчёт |
| `05_gmv_running_total.sql` | GMV нарастающим итогом | Накопленная выручка по дням | `SUM() OVER` |
| `06_top_day_per_user.sql` | День максимальной активности | Самый крупный день по тратам для каждого пользователя | `RANK() OVER (PARTITION BY)` |
| `07_days_between_orders.sql` | Паузы между заказами | Заказы после перерыва больше 5 дней | `LAG()` |

## Данные

`data/seed.sql` создаёт три таблицы:

- `events(user_id, event_date)` — одна строка = один заход пользователя
- `app_events(user_id, action)` — одна строка = одно действие в воронке
- `orders(order_id, user_id, order_date, amount)` — одна строка = один заказ

## Результаты на учебных данных

**Retention D7:** classic 30%, rolling 50%. Rolling всегда не меньше classic: он учитывает и тех, кто вернулся позже 7-го дня.

**Когорты:**

| cohort_date | users | D1 | D7 |
| --- | --- | --- | --- |
| 2026-10-01 | 4 | 50.0% | 25.0% |
| 2026-10-02 | 3 | 33.3% | 33.3% |
| 2026-10-03 | 3 | 66.7% | 33.3% |

**Sticky factor:** средний DAU 2.3 при MAU 10, то есть 23%.

**Воронка:** 6 → 3 → 1, конверсии 50% и 33.3%. Узкое место — signup → subscribe: у этого шага худшая конверсия.

## Решения, которые стоит проверить в коде

- **Знаменатель retention — вся когорта**, включая тех, кто не вернулся ни разу. Если взять только вернувшихся, retention будет завышен.
- **Считаются люди, а не события:** `COUNT(DISTINCT user_id)`. Пользователь, который дважды нажал signup, не завышает шаг воронки.
- **`* 100.0`, а не `* 100`:** при делении целых SQL отбрасывает дробную часть, и 2 / 3 превращается в 0.
- **`RANK`, а не `ROW_NUMBER`:** если у пользователя два дня с одинаковыми тратами, в ответ попадут оба (пользователь 2).
- **`LAG` у первого заказа возвращает `NULL`:** предыдущего заказа нет, и строка честно не проходит фильтр.

## Как запустить

Запросы совместимы с PostgreSQL и DuckDB. Сначала выполнить `data/seed.sql`, потом любой файл из корня.
